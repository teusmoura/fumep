# Leitura de sessão e logout isolados — MIG 3.6

`apps/backend/app/session_use_cases.py` usa o armazenamento Redis da MIG 3.1. `read(token)` retorna `user_id`, `role`, `institution_ids` e token CSRF da sessão ativa, ou `None` para ausência/expiração. O token CSRF é entregue intencionalmente na resposta autenticada conforme AUTH-002; não é o identificador do cookie e não deve ir a logs. Não retorna identificador da sessão, senha, hash nem tempos internos. A função não é autorização: o futuro endpoint/guard deverá revalidar o estado atual do usuário e suas permissões conforme a política MIG 3.4.

`logout(token, response, production=..., csrf_token=..., origin=..., referer=...)` exige o contrato CSRF para sessão válida, depois remove a sessão e expira o cookie `fumep_session` com Path=/, HttpOnly, SameSite=Lax e Secure em produção. Ausência, token inválido ou logout repetido são idempotentes sem exigir CSRF, conforme AUTH-002. Falha do Redis propaga erro e não confirma logout com expiração local apenas. Nenhuma rota foi criada nesta fatia.
