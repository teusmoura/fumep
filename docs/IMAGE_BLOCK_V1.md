# IMAGE v1

QA local em fixture temporário: 390×844 e 1280×900, LIGHT/DARK; fallback e alt contextual, caption literal escapada, decoração alt vazio/link nomeado pela caption, URL javascript bloqueada, aplicação por teclado/foco no status e foco visível. Sem overflow global, controles de edição com mínimo 44px e imagem sintética carregada. Sem erros/warnings no console. Fixture removido; não valida integração real do owner, persistência, publicação ou contraste global.

`imageBlockDataSchemaV1` define imageId UUID obrigatório, decorative boolean explícito, alt/caption opcionais de texto literal e link opcional seguro. Alt tem limite 300 e caption 500 caracteres; controles inseguros/extras/URLs físicas/HTML interpretado/CSS são recusados. O envelope compõe contrato comum com type IMAGE/schemaVersion 1. Alt ausente em draft informativo pode depender do fallback da Biblioteca; isso não aprova publicação.

`ImageBlockEditor` é Client independente, monta apenas initialValue estrutural válido, recebe projeções de imagens disponíveis e onApply. Remonte com key do bloco/proprietário/versão ao mudar conteúdo. IMAGE/READY/MIME permitido são filtrados pelo helper compartilhado com HERO. Referência atual fora da seleção bloqueia aplicação. Trocar imagem limpa alt contextual para evitar carregar descrição da imagem anterior. Alt contextual ou fallback da Biblioteca precisa cumprir limites/controles e não ser branco. Decoração é explicitamente marcada e produz alt vazio; imagem decorativa com link exige caption não branca para nome acessível do link.

O editor mantém dados inválidos para correção e valida antes de emitir, com callback async sem concorrência, fieldset disabled durante aplicação, recuperação de falha/status focável. Não faz rede/persistência, não copia Media nem concede autorização. Alt padrão não é copiado ao JSONB como referência de mídia: o UUID continua única referência primária e o consumidor deve resolver metadados atuais.

`ImageBlockRenderer` usa o mesmo envelope e descriptor `imageResolvedImageSchemaV1`: base disponível IMAGE/READY/NONE/MIME/dimensões/src do portal do HERO, acrescida de altText nullable/opcional validada. UUID deve corresponder. Alt contextual não branco tem preferência sobre fallback não branco; sem ambos, imagem informativa falha fechada. Decoração sempre rende alt="". Dados/versões/tipos/imagens inválidos ou ocultos retornam null. Rendering é SSR, figure/figcaption/Next/Image unoptimized, links seguros na mesma aba e strings escapadas por React, sem HTML/iframes/vídeo.

Layout é responsivo, imagem mantém proporção, caption tem largura de leitura e quebra de texto, controles reaproveitam escala/foco/44px do HERO e temas por tokens herdados. `frontendBlockRegistry` registra IMAGE v1 completo em PAGE/ARTICLE, mantendo HERO só PAGE e TEXT PAGE/ARTICLE. Nenhum contrato compartilhado importa React.

O descriptor é transporte fornecido pelo caller, não JSONB nem prova de disponibilidade/autorização. Backend futuro deve resolver imagem/URL realmente servida, acesso do owner, processamento/deleção atual, MediaUsage, Preview/publicação e completude acessível. Este loop não cria owner, rota de mídia pública, endpoint ou página navegável antecipados. Paths dos testes são fixtures sintéticos. Vitest/axe em jsdom cobrem segurança/alt/fallback/caption/links/estado; axe desativa contraste por ausência de layout, sem substituir QA visual completa/E2E.
