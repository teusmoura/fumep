# Exclusão de bloco — 5.13

PageBuilder solicita confirmação local inline, com aviso sobre edits não aplicados daquele bloco. Excluir inicialmente não emite callback; Confirmar exclusão/Cancelar exclusão são controles nomeados/focáveis por teclado. Enquanto confirmação está aberta, outras ações/editores ficam bloqueados, mantendo estado. Cancelar preserva tudo. Confirmar emite snapshot clonado validado do draft sem o bloco, normalizando posições; só sucesso remove o bloco da lista. Falha permite repetir/cancelar sem perder dados; ref bloqueia callback concorrente. Blocos restantes usam IDs estáveis, preservando seus edits locais. Último bloco pode ser removido para draft vazio. Sem endpoint de persistência/Preview/publicação neste loop.

ContentBlockRepository.deleteForOwner(ownerType, ownerId, blockId) é consumidor interno Drizzle, não autoridade derivada de UUID/browser. Caller deve resolver/autorizar o parent real e integrar seu salvamento na mesma transação externa. Repository valida formato/contexto, obtém advisory transaction lock do parent (hashtext de CONTENT_BLOCK_OWNER:PAGE/ARTICLE e UUID normalizado), verifica bloco/owner com FOR UPDATE, remove usos entity_type CONTENT_BLOCK/entity_id blockId via MediaUsageRepository(tx) e remove linha atual na mesma transação. Owner errado/ausência não remove usos; repetição retorna false. Saves futuros devem usar o mesmo lock de parent e verificar existência/lock do bloco antes de sincronizar seus usos, para não recriar usos depois da exclusão.

Namespace CONTENT_BLOCK identifica a entidade real que contém data/background_media_id; fields controlados identificam cada referência (por exemplo data.imageId). Não há integração anterior de Page Builder a migrar. Não remover todos os usos PAGE/ARTICLE do parent, usos de outros blocos ou usos PAGE_VERSION/ARTICLE_VERSION. Publisher/version consumer futuro deve manter seus próprios usos históricos: excluir bloco atual não libera referências de versões. Snapshot JSONB antigo não é reescrito, nem linha PageVersion/ArticleVersion removida. Tests criam snapshot/usos de versão somente como fixture, sem implementar publicação/versionamento antecipado.

Repository não importa storage, não apaga Media/variantes/objeto MinIO, não cria jobs, tabelas ou migrations. Mídia compartilhada permanece protegida por outros usos/FK RESTRICT. Remoção de usos e bloco participa de rollback externo. O callback frontend ainda não é transporte REST: na fase 6 o caller/backend deve integrar deleteForOwner para blocos removidos e sincronização dos conteúdos persistidos, com guards de autorização/CSRF/concurrency aplicáveis. Audit de Page Builder pertence ao 6.10.

Testes reais PostgreSQL: owner incorreto/referência inválida, rollback, compartilhamento/snapshot/usos históricos preservados, concorrência/idempotência. UI: confirmação/cancelamento/falha/retry/concurrency, draft vazio, edits de outro editor retidos, posições/contexto e axe semântico (sem contraste jsdom). Sem test:e2e, certificação de contraste global ou integração owner REST real.
